# Stable UNIX root alias control plane

The existing virtual root expands a valid short guest UNIX pathname into a host-prefix pathname that may exceed Linux sun_path. A source-level bound prevents wrong endpoint truncation but cannot make that valid guest address work. The new caller-root RPC supplies a stable short /proc/PID/fd/FD root spelling, so Linux binds the original ordinary socket inode inside the prefix instead of a separate transport namespace.

The RPC is appended to preserve existing wire numbers. It derives the process from the existing authenticated thread; the caller supplies only an output buffer/capacity, never a PID/root/FD. Process snapshots its shared root descriptor and canonical path under one lock. The actual registry validates directory/inode and its current descriptor link against the canonical path, duplicates it with F_DUPFD_CLOEXEC, and retains that owner until server exit. Entries are keyed by device/inode/canonical path, deduplicated and bounded at256 without unsafe live eviction. Root rename/deletion mismatch fails ESTALE; it does not silently reassign an old alias. Canonical vchrootPath behavior is unchanged.

The server obtains its numeric PID from its own /proc/self link and validates decimal range, matching the procfs mount used by the alias. This is an explicit implementation policy, not a claim of an observed PID mismatch: the actual coordinator server proof had matching getpid/proc-self views. The sandbox native mapping test failed bind EPERM, which did not establish a namespace cause. Actual client traversal still requires compatible accessible procfs views; RPC metadata cannot make an inaccessible /proc descriptor work. No ptrace/proc/security setting is changed.

`tests/unix-root-rpc-numbers.py` generates both exact parent9353d34 and candidate protocol maps; all existing values stay identical and only vchroot_socket_root is appended.

`tests/unix-root-registry.cpp`, linked to actual src/unix-root-alias.cpp and src/utility.cpp, runs under ASan/UBSan. It verifies actual alias marker identity, original-owner destruction, stable dedup with a fresh input FD, CLOEXEC, path mismatch and rename ESTALE, non-directory failure,256entry resource bound and no eviction before exit. The source test passes; no mock registry or process-ID claim is used. LSan is disabled for this runner's known restriction.

Actual process/call/module production objects compile isolated with freshly generated candidate RPC headers. End-to-end guest RPC/long-prefix transport, different-process path return after client exit, actual vchroot changes and cross-prefix isolation remain coordinator runtime gates. The separate xnu component implements checked mapping and includes original guest/native fixtures. This does not qualify Keka, DNC API completeness, abstract UNIX names or any host protocol defaults.
